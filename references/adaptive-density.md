# Adaptive Density — 큰 본문과 빈 공간 균형 규칙

이 문서는 `report-carousel-v3.1-large-type-adaptive-fill`의 핵심 조판 알고리즘이다.

목표는 두 가지다.

1. 인스타그램 모바일 화면에서 원문 본문이 충분히 크게 읽힐 것
2. 고정 패널 때문에 의미 없는 빈 공간이 남지 않도록 사진·패널·표·문단 경계를 텍스트 실측값에 맞출 것

## 1. 기본 철학: 텍스트를 먼저 재고, 레이어를 나중에 만든다

기존 방식처럼 사진 슬롯과 패널 높이를 먼저 정한 뒤 작은 글자를 억지로 넣지 않는다.

제작 순서:

1. 제목·부제목·본문을 고정 폰트로 먼저 조판한다.
2. 실제 텍스트 bounding box 높이를 계산한다.
3. 필요한 패널 높이를 `텍스트 높이 + 상하 패딩`으로 계산한다.
4. 남은 공간을 사진 또는 표에 배분한다.
5. 빈 공간과 오버플로를 수치로 검사하고 페이지 맵을 재조정한다.

폰트는 레이어에 맞추지 않는다. **레이어가 텍스트에 맞춘다.**

## 2. 읽기 프리셋

한 데크는 시작 전에 아래 둘 중 하나를 선택한다. 장마다 임의로 바꾸지 않는다.

### `reading-large` — 기본값

편집형 콘텐츠, 일반 리포트, 사진 중심 캐러셀에 사용한다.

```yaml
body: 23
body_line_height: 35
caption: 18
caption_line_height: 27
table: 15
table_line_height: 22
table_header: 15
table_header_line_height: 22
reference: 11
reference_line_height: 16
```

### `source-dense-large`

원문 전체 보존 + 고정 장수 + 장문이 동시에 필요한 경우에만 사용한다.

```yaml
body: 21
body_line_height: 32
caption: 17
caption_line_height: 25
table: 14
table_line_height: 20
table_header: 14
table_header_line_height: 20
reference: 11
reference_line_height: 16
```

강제 규칙:

- 17px 본문을 기본값으로 쓰지 않는다.
- 오버플로를 이유로 특정 장만 폰트를 줄이지 않는다.
- 프리셋 변경은 렌더링 전에 데크 전체에 적용한다.
- 물리적으로 수용할 수 없으면 사진 면적·열 구성·페이지 경계를 조정한다.

## 3. 제목 계층

1080×1350 기준:

```yaml
label: 28/34
main_title: 56/66
section_title: 36/47
subtitle: 30/41
page_number: 30
credit: 22
```

- 같은 역할의 제목은 전 장에서 동일하다.
- 긴 제목은 줄바꿈한다.
- 제목 때문에 본문 공간이 부족하면 사진 면적을 줄이거나 다음 장으로 나눈다.

## 4. 동적 패널 계산

모든 패널은 8px 그리드로 계산한다.

```text
required_panel_height
= top_padding
+ title_height
+ title_body_gap
+ body_height
+ bottom_padding
```

권장 패딩:

```yaml
top_padding: 28~40
bottom_padding: 28~40
left_right_padding: 34~48
title_body_gap: 20~28
```

`photo-bottom-panel`은 small/medium/large 고정 3단계만 사용하지 않는다.

```text
panel_top = floor_to_8(footer_safe_top - required_panel_height)
```

제약:

- 패널 높이 최소 330px
- 패널 높이 최대 930px
- 최소값보다 작으면 사진을 더 크게 쓴다.
- 최대값보다 크면 사진 영역을 줄이거나 `body` 타입으로 바꾼다.

## 5. 사진 영역 계산

사진은 패널의 남은 공간을 받는다.

```text
photo_height = panel_top - photo_top - gap
```

- 전경 사진은 contain, 무크롭
- 빈 공간은 같은 사진의 blur/cover 배경으로 채운다.
- 텍스트가 적으면 패널을 줄이고 사진을 확대한다.
- 텍스트가 많으면 사진을 줄이되, 핵심 피사체가 충분히 보이지 않으면 사진을 제거하고 `body`로 전환한다.

## 6. 페이지 채움 지표

푸터와 안전 여백을 제외한 영역을 `usable_area`로 정의한다.

### 세로 채움률

```text
vertical_fill
= (마지막 의미 요소의 하단 - 첫 의미 요소의 상단) / usable_height
```

목표:

```yaml
normal_page: 0.86~0.97
cover_or_chapter: 0.72~0.94
```

### 패널 활용률

```text
panel_utilization
= text_bbox_height / panel_inner_height
```

목표:

```yaml
min: 0.72
max: 0.92
```

- 0.72 미만이면 패널이 과도하게 크다. 패널을 줄이고 사진을 키운다.
- 0.92 초과면 너무 조밀하다. 사진을 줄이거나 텍스트를 다음 장으로 넘긴다.

### 눈에 띄는 빈 띠

다음은 의도하지 않은 빈 공간으로 본다.

- 140px 이상 연속된 빈 세로 띠
- usable height의 10% 이상인 무의미한 빈 영역
- 본문 종료 후 푸터까지 180px 이상 남는 보고서 페이지

표지·챕터 오프닝의 의도적 여백만 예외다.

## 7. 빈 공간 해결 우선순위

빈 공간이 기준을 넘으면 다음 순서로 해결한다.

1. 패널을 텍스트 높이에 맞게 줄인다.
2. 사진을 남은 공간까지 확대한다.
3. 같은 섹션의 다음 문단을 앞 페이지로 당긴다. 문장 순서는 유지한다.
4. 가로 사진 1장을 `photo-stack` 또는 `photo-duo`로 바꿔 관련 사진을 추가한다.
5. 원문에 있는 한 문장·수치·기록을 `source-highlight`로 크게 승격한다. 본문에서 중복하지 않는다.
6. 1열을 2열로 바꾸거나, 2열을 1열로 되돌려 균형을 맞춘다.
7. 적합한 사진이 없으면 사진을 억지로 넣지 않고 `body-balanced`로 전환한다.

금지:

- 빈 공간을 장식 아이콘·의미 없는 박스·가짜 그래프로 채우기
- 장마다 본문 폰트 크기 바꾸기
- 문장을 반복해 공간 채우기

## 8. 원문 페이지 재균형

전체 source order는 유지하면서 페이지 경계만 움직인다.

두 번의 패스를 사용한다.

### Pass 1 — 용량 분할

고정 폰트와 페이지 타입으로 각 페이지 수용량을 계산해 문단을 배치한다.

### Pass 2 — 인접 페이지 균형

- underfill 페이지는 다음 페이지의 완전한 문장 또는 문단을 앞당긴다.
- overfill 페이지는 마지막 완전한 문장 또는 문단을 다음 장으로 넘긴다.
- 제목 뒤 최소 2줄의 본문을 남긴다.
- 한 문단의 첫 줄 또는 마지막 한 줄만 홀로 남기지 않는다.
- 표 행은 분리하지 않는다.
- 10→11장 같은 구간도 동일한 page map으로 연속 검수한다.

## 9. `source-highlight` 타입

원문에 이미 존재하는 한 문장, 기록, 숫자를 큰 시각 요소로 승격할 수 있다.

예:

- `1:53.70`
- `세계 기록까지 0.42초`
- `6개월 만에 4초 단축`

규칙:

- 새로운 주장이나 해석을 만들지 않는다.
- 원문 속 해당 구절을 본문에서 제거하고 highlight로 한 번만 표시한다.
- text manifest에는 원래 순서대로 한 번만 기록한다.
- 36~52px 범위의 별도 highlight 폰트를 사용한다.

## 10. 표 페이지 채움

표 페이지에는 사진을 넣지 않는다.

빈 공간 해결 순서:

1. 표 폰트를 읽기 프리셋 크기로 유지한다.
2. 행 높이를 균등 또는 콘텐츠 비례로 확대한다.
3. 표 전체를 제목 아래부터 푸터 위까지 수직 균형 배치한다.
4. 원문에 있는 도입 문장·참고 문장을 표 전후에 배치한다.
5. 필요한 경우 표를 2장으로 나누되, 각 장의 행 높이와 폰트는 동일하게 유지한다.

목표:

```yaml
table_vertical_fill: 0.72~0.92
minimum_row_height: 64
maximum_row_height: 118
```

## 11. 완료 실패 조건

다음 중 하나라도 있으면 재렌더링한다.

- 일반 본문이 20px 미만
- 장마다 본문 폰트가 다름
- 패널 활용률 0.65 미만 또는 0.96 초과
- 의도하지 않은 140px 이상 빈 띠
- 사진이 작게 떠 있고 주변에 불필요한 여백이 큼
- 본문이 짧은데 패널이 화면 절반 이상을 차지함
- 표가 화면 상단에 몰리고 하단이 크게 비어 있음
- 빈 공간을 이유로 원문을 반복하거나 장식 요소를 추가함

## 12. 기본 선언

**본문을 먼저 크게 읽히게 조판하고, 사진·패널·표 레이어를 텍스트 실측값에 맞춰 유동적으로 조정한다.**

**폰트는 레이어에 맞추지 않고, 레이어가 폰트와 텍스트에 맞춘다.**
