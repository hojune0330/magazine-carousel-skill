# Adaptive Density v3.3 — 본문을 확보한 뒤 사진을 맞춘다

활성 프로필: `report-carousel-v3.3-text-first-audience-clean`.

## 1. 기본 원칙

본문은 26px/39px를 새 기본으로 고정한다. 사진을 먼저 크게 잡아 23px·21px로 본문을 내려 맞추지 않는다. 기존 승인본의 실제 스타일이 있으면 그것을 계승한다.

우선순위: 원문 완전성 → 잘림·가림 없음 → 고정 가독성 → 문단 흐름 → 보조 사진·그래프 → 미감.

## 2. 실측 순서

1. 선택 원문의 제목·본문·표·각주를 모두 식별한다.
2. 원문 앞에서 뒤로 고정 폰트로 줄바꿈한다. 실제 draw 문자열과 원문 범위를 연결한다.
3. 제목·본문·표의 높이와 고정 푸터 안전 영역을 계산한다.
4. 먼저 전체 원문의 페이지 배치를 완료한다.
5. 남는 공간과 내용에 맞는 사진만 넣는다.

`panel_height = 실제 텍스트 높이 + 필요한 상하 패딩`이다. 예전 패널 최소 330px 규칙 때문에 짧은 본문 뒤에 커다란 공백을 만들지 않는다.

## 3. 2-pass 재균형

Pass 1: 고정 폰트로 원문 전체 배치.

Pass 2: 인접 페이지 사이의 완전한 문장·문단을 옮겨 넘침과 과도한 빈 공간을 줄인다. 원문 순서는 유지한다. 명시적 재배열 모드에서는 승인된 블록 순서를 유지한다.

표 행은 중간에서 잘라 놓지 않는다. 제목 바로 다음 본문 최소 2줄, 문단의 첫·끝 한 줄 고립을 피한다.

## 4. 오버플로 해결 순서

1. 보조 그래프·장식·사진 제거 또는 축소.
2. 불필요한 제작 메타 라벨 제거. 원문은 삭제하지 않음.
3. 패널 패딩과 문단 간격을 승인 범위 안에서 조정.
4. 완전 문단을 다음 장으로 넘김.
5. 실제로 읽히는 2열 레이아웃을 시험. 더 좁은 열이 반드시 용량을 늘리지는 않으므로 실측.
6. 원문 표를 행 단위로 분할.
7. 정확한 장수와 고정 폰트가 충돌하면 필요한 조정을 설명하고 승인받음.

페이지별 폰트 축소, 줄 수 제한, 말줄임표, 보이지 않는 overflow:hidden으로 해결하지 않는다.

## 5. 빈 공간 처리

140px 이상의 빈 띠 또는 본문 끝~푸터 180px 이상의 간격은 검토 신호로 기록한다. 이를 전부 나쁜 여백으로 판정하지 않는다.

- 다음 문단을 당겨도 원문 흐름이 자연스러운가?
- 사진을 넣으면 실제 이해에 도움이 되는가?
- 근거가 있는 보조 자료가 들어갈 충분한 공간인가?
- 제목·표 단위 때문에 남긴 의도적인 여백인가?

해결 수단이 없으면 이유를 내부 보고서에 적고 깨끗한 여백으로 남긴다. 슬라이드에 `공백 예외`, `QA 통과`라고 표시하지 않는다.

## 6. 보조 시각물 계약

본문은 항상 전부 남는다. 추가 차트·사진이 들어갈 때마다 원문 범위, 텍스트 크기, 이미지 가림, footer 침범을 다시 검사한다. 사진이 작아 의미를 잃으면 없애고 텍스트 장으로 완성한다.
