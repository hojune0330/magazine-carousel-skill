# Report Carousel v2.1 Photo

## 상태

```yaml
profile: report-carousel-v2.1-photo
status: active
typography_reference: approved-report-pages-11-20
photo_composition_reference: approved-photo-carousel-pages-01-10
rejected_reference: generative-poster-pages-11-20
```

이 문서는 고정된 보고서 타이포그래피와 사용자가 승인한 사진 중심 01~10장 제작 방식을 결합한 공식 시각 명세다.

## 1. 핵심 성격

- 인스타그램 4:5 세로형
- 사진이 주인공인 정보형 리포트
- 전경 사진은 원본 비율 유지, 무크롭
- 남는 영역은 같은 사진의 블러·확대·톤다운 배경으로 채움
- 장문은 웜화이트 불투명/반투명 패널 안에 배치
- 표 페이지는 사진 없이 순수 보고서형으로 제작
- 같은 역할의 제목·본문·표·푸터 크기 고정
- 생성형 이미지에 한국어 본문과 표 조판을 맡기지 않음

```yaml
background: "#F8F7F4"
```

- 노란색은 좌상단 바와 꼭 필요한 강조에만 사용한다.
- 표 페이지에는 단색 웜화이트 배경만 사용한다.
- 그림자, 광택, 네온, 장식 그라디언트는 사용하지 않는다.

2. Noto Sans CJK KR

### 강제 규칙

- 같은 역할의 제목끼리 크기를 바꾸지 않는다.
- 같은 역할의 본문끼리 크기와 줄간격을 바꾸지 않는다.
- 같은 표 안에서 역할별 글자 크기를 바꾸지 않는다.
- 공간이 부족하면 페이지를 나누고 글자를 줄이지 않는다.
- 자간을 과도하게 줄여 내용을 끼워 넣지 않는다.

## 5. 공통 요소

### 라벨

```yaml
bar:
  x: 45
  y: 34
  width: 10
  height: 42
label_text:
  x: 72
  y: 38
  default: "ELITE REPORT"
```

### 푸터

- 좌하단: `01 / 20`
- 우하단: `@io_magazine / 장호준 코치`
- 구분선, 번호, 크레딧의 위치는 모든 장에서 고정한다.
- 사진 페이지에서는 사진 위 또는 패널 위에 놓을 수 있으나 같은 좌표를 사용한다.

## 6. 사진 합성 원칙

### 전경과 배경의 역할 분리

1. 배경 레이어: 같은 사진을 슬롯 전체에 cover로 확대하고 24~32px 블러 처리한다. 필요한 경우 검정 또는 흰색을 8~25% 혼합한다.
2. 전경 레이어: 원본 비율을 유지해 contain으로 배치한다. 전경은 크롭하지 않는다.
3. 텍스트 레이어: 사진 위에 긴 문장을 직접 얹지 않고 패널을 사용한다.

### 핵심 피사체 보존

- 얼굴, 머리, 손, 발, 허들, 결승선, 메달 등 핵심 정보가 전경에서 잘리면 실패다.
- 가로 사진을 좁은 세로 슬롯에 억지로 넣지 않는다.
- 사진의 방향과 본문의 길이에 따라 페이지 타입을 선택한다.

## 7. 페이지 타입

### 7.1 `cover-photo`

- 사진을 화면 전체 배경으로 사용한다.
- 전경은 무크롭으로 중앙 배치한다.
- 제목과 짧은 설명은 하단 또는 좌측 패널에 둔다.

### 7.2 `photo-bottom-panel`

```yaml
photo_region:
  x: 0
  y: 0
  width: 1080
panel_presets:
  compact_top: 760
  medium_top: 650
  long_top: 520
```

- 사진이 상단에서 크게 보이도록 한다.
- 본문 길이에 따라 세 가지 패널 높이 중 하나를 사용한다.
- 패널 높이는 프리셋으로 선택하고 글자 크기는 바꾸지 않는다.

### 7.3 `photo-top-report`

```yaml
photo_region_presets:
  short_text_height: 560
  medium_text_height: 470
  long_text_height: 390
```

- 사진을 상단 29~42%에 무크롭으로 배치한다.
- 하단 보고서 영역은 1열 또는 2열로 구성한다.
- 장문 분석에 적합하다.

### 7.4 `photo-split`

- 세로형 인물 사진 또는 충분히 짧은 본문에만 사용한다.
- 사진과 텍스트 패널 비율은 콘텐츠에 맞는 고정 프리셋을 선택한다.
- 가로 경기 사진에는 사용하지 않는다.

### 7.5 `table`

- 제목 + 짧은 도입 + 표
- **사진 사용 금지**
- 웜화이트 단색 배경
- 검정 상·하단선과 회색 내부선 사용
- 표가 넘치면 다음 장으로 분할

### 7.6 `body`

- 적합한 사진이 없거나 사진이 정보 전달을 방해할 때 사용한다.
- 제목 + 장문 본문으로 구성한다.

### 7.7 `sources`

- 결론과 출처를 함께 구성할 수 있다.
- 긴 URL은 두 열로 나누고 글자 크기를 고정한다.

## 8. 표 규칙

- 표 뒤와 표 옆에 사진을 사용하지 않는다.
- 인물 얼굴이나 경기 장면을 워터마크로 깔지 않는다.
- 열 너비는 데이터 유형에 따라 고정 비율로 설정한다.
- 행 높이는 셀의 줄 수에 맞춰 늘릴 수 있다.
- 표가 푸터를 침범하면 2장으로 분할한다.
- 셀 텍스트를 맞추기 위해 축소하지 않는다.

## 9. 온라인 이미지 규칙

- 공식 경기 기관 또는 Wikimedia Commons의 명확한 자유 라이선스 사진을 우선한다.
- 이미지 원문 페이지, 작가, 라이선스, 변경 여부를 `IMAGE_SOURCES.md`에 남긴다.
- 결과물에는 필요 시 짧은 사진 크레딧을 넣고, 전체 라이선스 정보는 ZIP에 포함한다.
- 출처 불명 이미지와 검색 결과 썸네일을 직접 저장해 사용하지 않는다.

## 10. 원문 보존 모드

- 문자를 수정하지 않는다.
- 제목과 표 셀도 원문 그대로 사용한다.
- 문장 순서를 바꾸지 않는다.
- 페이지 구분과 줄바꿈만 허용한다.
- 각 페이지 텍스트를 `text-manifest.txt`에 기록한다.
- 원본 전체 문자열과 페이지 텍스트 연결 문자열을 비교한다.
- 누락 문자 수가 0이 아니면 완료로 처리하지 않는다.

## 11. 필수 산출물

- 개별 PNG
- 일괄 ZIP
- 콘택트시트
- `text-manifest.txt`
- `IMAGE_SOURCES.md`
- `QA_REPORT.md`
- 남은 원문이 있으면 별도 텍스트 파일

## 12. 실패 조건

- 생성형 이미지 안에서 한국어 장문 또는 표를 생성했다.
- 제목·본문·표의 역할별 폰트가 장마다 달라졌다.
- 전경 사진의 얼굴·발·핵심 동작이 잘렸다.
- 표 페이지에 사진을 넣었다.
- 텍스트를 맞추기 위해 글자를 줄였다.
- 사진 때문에 본문 가독성이 떨어졌다.
- 원문에서 문자·숫자·각주·URL·표 셀이 누락됐다.
- 이미지 출처 파일이 없다.
