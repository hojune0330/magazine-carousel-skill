# Report Carousel v2

## 상태

```yaml
profile: report-carousel-v2
status: active
authorized_reference: approved-pages-11-20
rejected_reference: pages-1-10
```

이 문서는 사용자가 승인한 11~20장 규격을 재현하기 위한 공식 시각 명세다. 1~10장 규격은 폐기됐으며 혼용하지 않는다.

## 1. 핵심 성격

- 인스타그램 4:5 세로형
- 장문을 수용하는 보고서형 레이아웃
- 흰색에 가까운 웜그레이 배경
- 검정 타이포그래피
- 좌상단 노란 세로 바와 영문 라벨
- 큰 제목, 차분한 본문, 얇은 표와 구분선
- 모든 장에 고정된 페이지 번호와 크레딧
- 사진을 넣어도 상단과 하단 구조가 흔들리지 않는 시스템

## 2. 캔버스

승인본은 1122×1402로 렌더링됐다. 실제 게시용 기본 캔버스는 1080×1350을 사용하고 모든 좌표를 비례 축소한다.

```yaml
production_canvas:
  width: 1080
  height: 1350
  aspect_ratio: 4:5
reference_canvas:
  width: 1122
  height: 1402
```

## 3. 색상

```yaml
background: "#FAF9F6"
ink: "#121212"
muted: "#505050"
hairline: "#BEBEBE"
table_grid: "#CBCBCB"
accent_yellow: "#FFD300"
```

- 배경색은 데크 전체에서 바꾸지 않는다.
- 노란색은 상단 바와 꼭 필요한 한 곳에만 쓴다.
- 그림자, 광택, 네온, 과도한 그라디언트를 쓰지 않는다.

1080×1350 기준:

```yaml

  width: 12
  height: 57

  x: 104

  x: 70
```

정규화 비율:

```yaml

footer_text_top: 90.66%
```

다른 해상도로 제작할 때는 비율을 유지한다.

## 5. 고정 타이포그래피

사용 가능 우선순위:

1. Pretendard
2. Noto Sans CJK KR
3. Noto Sans KR

폰트 파일은 저장소에 포함하지 않는다.

### 강제 규칙

- 제목끼리 크기를 바꾸지 않는다.
- 부제목끼리 크기를 바꾸지 않는다.
- 원문 본문끼리 크기를 바꾸지 않는다.
- 표 안의 같은 역할 글자끼리 크기를 바꾸지 않는다.
- 공간이 부족해도 축소하지 않는다.
- 제목이 길면 줄바꿈한다. 그래도 넘치면 다음 장 또는 별도 챕터 장으로 나눈다.
- 본문이 넘치면 다음 장으로 이어간다.

## 6. 공통 헤더와 푸터

### 헤더

- 노란 세로 바와 영문 라벨을 모든 장에 반복한다.
- 기본 라벨은 `ELITE REPORT`다.
- 콘텐츠에 따라 `SEASON REPORT`, `ATHLETE REPORT`, `TRAINING REPORT`, `DATA REPORT`를 쓸 수 있다.
- 한 데크에서는 라벨을 한 종류로 고정하는 것을 기본으로 한다.

### 푸터

- 좌하단: `01 / 20`
- 우하단: `@io_magazine / 장호준 코치`
- AthleteTime 콘텐츠는 `@athletetime / 장호준 코치`를 쓸 수 있다.
- 페이지 번호, 구분선, 크레딧의 위치와 크기는 모든 장에서 고정한다.

## 7. 제목과 본문 영역

- 제목은 `y=212`에서 시작한다.
- 제목 줄 높이는 62px다.
- 제목 뒤 기본 간격은 24~30px다.
- 본문 시작 위치는 제목 줄 수에 따라 내려가지만 본문 글자 크기와 줄 높이는 변하지 않는다.
- 본문 최대 하단은 푸터 구분선 위 24px다.
- 본문은 좌측 정렬한다.
- 장문 보고서에서는 F-시선 강박보다 안정적인 문단 흐름을 우선한다.

## 8. 페이지 타입

### 8.1 `cover`
- 제목만으로 주제를 설명한다.
- 제목은 고정 크기를 유지한다.
- 여백을 크게 둔다.
- 필요 시 짧은 설명 한 문단만 추가한다.

### 8.2 `body`
- 제목 + 원문 또는 분석 본문
- 본문은 17px/26px로 고정한다.
- 문단 사이 한 줄을 둔다.
- 넘치면 자동 축소하지 않고 다음 장으로 이어간다.

### 8.3 `table`
- 제목 + 짧은 도입 + 표
- 표는 검정 상단선, 회색 내부선, 검정 하단선으로 구성한다.
- 셀 텍스트는 가운데 정렬을 기본으로 한다.
- 표 안의 문장이 길면 행 높이를 늘린다.
- 표가 넘치면 2장으로 나눈다.

### 8.4 `summary`
- 제목 + 3~5개 항목
- 각 항목의 제목과 설명 위치를 반복한다.
- 장식 아이콘은 필요할 때만 쓴다.

### 8.5 `sources`
- 제목은 동일한 위치와 크기를 유지한다.
- 출처 글자는 9px로 고정한다.
- URL이 길어도 글자를 줄이지 않고 줄바꿈한다.

## 9. 사진 결합형 슬롯

사진이 들어가도 헤더, 제목, 푸터 좌표는 바꾸지 않는다.

### A. `photo-hero`

```yaml
photo:
  x: 70
  y: 455
  width: 940
  height: 390
caption_or_body_y: 875
```

- 경기 장면, 선수 전신, 행사 현장에 적합하다.
- 사진은 가로 크롭한다.
- 사진 위에 긴 본문을 올리지 않는다.

### B. `photo-split`

```yaml
photo:
  x: 70
  y: 455
  width: 420
  height: 620
text:
  x: 525
  y: 455
  width: 485
```

- 선수 프로필, 코치 인터뷰, 제품·동작 설명에 적합하다.
- 사진과 본문의 상단선을 맞춘다.

### C. `photo-data`

```yaml
photo:
  x: 70
  y: 455
  width: 590
  height: 610
data_rail:
  x: 695
  y: 455
  width: 315
```

- 선수 사진 옆에 기록, 국적, PB, 시즌 성과를 배치한다.
- 데이터 레일은 박스 남발 없이 구분선과 타이포 위계로 만든다.

### D. `photo-duo`

```yaml
left_photo:
  x: 70
  y: 455
  width: 455
  height: 450
right_photo:
  x: 555
  y: 455
  width: 455
  height: 450
body_y: 940
```

- 두 선수, 두 동작, 전후 비교에 적합하다.
- 두 사진의 크롭 비율과 눈높이를 맞춘다.

## 10. 사진 편집 규칙

- 인물의 얼굴, 머리, 발, 주 동작을 이유 없이 자르지 않는다.
- 사진은 최소 2배 해상도로 준비한 뒤 최종 크기에 맞춰 축소한다.
- 사진의 밝기와 색온도를 데크 전체에서 통일한다.
- 과한 라운드, 그림자, 테두리, 스티커를 쓰지 않는다.
- 사진 위 텍스트는 짧은 캡션이나 수치만 허용한다.
- 사진이 없으면 억지 생성형 이미지를 채우지 않고 본문형 페이지로 전환한다.

## 11. 원문 보존 모드

- 문자를 수정하지 않는다.
- 제목도 원문 제목을 그대로 사용한다.
- 표의 제목, 열 이름, 셀 값도 그대로 사용한다.
- 페이지 구분 때문에 문단을 나눌 수는 있지만 문장 순서는 바꾸지 않는다.
- 각 페이지의 텍스트를 매니페스트로 저장한다.
- 원본 전체 문자열과 매니페스트 연결 문자열을 비교한다.
- 줄바꿈 차이는 허용하되 문자 누락은 허용하지 않는다.

## 12. 실패 조건

아래 중 하나라도 있으면 완료로 보지 않는다.

- 제목 크기가 장마다 다르다.
- 본문 크기가 장마다 다르다.
- 제목 시작 위치가 흔들린다.
- 사진 장에서 푸터가 이동한다.
- 본문이 푸터를 침범한다.
- 표를 맞추기 위해 글자를 축소했다.
- 원문 보존 모드에서 글자, 숫자, 각주, URL이 누락됐다.
- 콘택트시트에서 1~10장식 불안정한 규격이 섞여 보인다.
