# Copy Guard v3.3 — 자료 선택부터 실제 픽셀 노출까지

## 1. 선택 원문 잠금

사용자가 말한 `지금 자료`, `처음 보고서`, `원문 전체`를 대화·파일에서 확인한다. 분량이 짧다는 이유로 예전 축약 text-manifest를 원문으로 선택하지 않는다.

`source.txt`는 원본 바이트 그대로 보관하고 SHA-256을 기록한다. 유니코드·띄어쓰기·문장부호를 자동 교정하지 않는다. 비교 편의를 위한 정규화본이 필요하면 별도로 만들고 변환 규칙을 기록한다.

## 2. 보존 범위

제목·소제목·문단·문장·숫자·괄호·원문 표의 헤더와 셀·각주·URL을 실제 슬라이드에 넣는다. ZIP에 source.txt를 넣어 두는 것으로 누락을 보완하지 않는다.

보조 그래프·사진·새 제목은 원문을 대체할 수 없다. 원래 표는 원문이므로 표 자체를 유지한다.

## 3. 기본 순서

`preserve-exact`에서는 첫 source_start=0, 마지막 source_end=len(source), 인접 end/start 동일을 검사한다. 페이지 범위가 겹치거나 비면 실패다.

각 원문 블록의 `source_ranges`를 시각 노드에 연결한다. title/body/table 등 어디에 놓였든 연결 원문이 정확히 한 번 노출되어야 한다.

## 4. 재배열은 별도 승인

사용자가 `구조만 바꿔`, `결론을 앞으로`라고 명시하면 `reorder-without-rewrite`를 사용할 수 있다. 블록 ID 순열을 만들고 각 블록이 정확히 한 번 포함되었는지 검사한다. 이 모드에서 전역 단조 증가 조건을 억지로 적용하지 않는다. 블록 내부 문장·숫자는 그대로다.

`요약하지 마`만으로 재배열이 허용되는 것은 아니다.

## 5. 제작 메타정보

렌더러가 덧붙인 FULL TEXT, 첨부파일 안내, QA 라벨은 원문의 일부가 아니다. 삭제 권한이 있는 제작 메타정보는 공개층에서 제외하고 production 문서에 남긴다.

반대로 원문에 실제 있는 `본 보고서는`, 연구 방법, 출처, 논문 제목은 무차별 삭제하지 않는다. 애매한 문장은 원문 보존 범위와 공개 필요도를 확인하고 예외 사유를 기록한다.

## 6. 강조와 추가 시각화

원문 구절을 대형 강조로 승격하면 원래 순서와 전체 구절을 유지하고 별도로 복제하지 않는다. 원문 그래프화는 보존의 대체가 아니다.

보조 차트의 수치·단위 반복, 필수 출처·브랜드·페이지 번호는 원문과 구분해 `supplemental` 또는 비원문 provenance로 기록한다. 이 추가 라벨을 원문 중복이라고 잘못 세지 않되 본문을 빼는 근거로 사용하지 않는다.

## 7. 이중 검사

A. 원문 범위 검사: page-map의 source 범위를 조합해 원문 해시·문자·순서·표 셀을 대조한다.

B. 실제 렌더링 검사: 모든 텍스트 draw call의 문자열과 source_ranges를 기록하여 지도에만 있고 그려지지 않은 본문이 없는지 확인한다. 실제 glyph 경계와 가림 여부는 별도 시각 검사한다.

검사하지 않은 수치를 0으로 채우지 않는다. 실패·미실행은 있는 그대로 보고한다.

## 8. 공간 부족과 사실 검토

보조 이미지를 먼저 빼고 페이지 경계·열·표 행 분할을 조정한다. 원문을 요약하거나 페이지별 본문 크기를 줄이지 않는다. 고정 장수와 충돌할 때만 승인할 선택지를 제시한다.

의심되는 사실·오탈자는 `CONTENT_REVIEW_NOTES.md`에 분리한다. 원문 보존을 검증 완료나 사실 보증으로 표현하지 않는다. 독자 오해를 막기 위한 필수 주의사항은 제작 메타정보가 아니라 콘텐츠로 취급한다.
