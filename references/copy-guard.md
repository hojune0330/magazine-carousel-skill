# Copy Guard v3 — 원문 보존·연속성 규칙

사용자가 `원문 그대로`, `한 글자도 빼지 말 것`, `단어·문장·표를 모두 유지`, `내용 빠짐없이`라고 지시하면 이 문서를 강제한다.

## 1. 원문 잠금

- 사용자가 준 원문 전체를 `source.txt`로 저장한다.
- 원문의 SHA-256 해시와 문자 수를 기록한다.
- 이후 모든 페이지 문구는 source.txt에서 가져온다.
- 채팅 기억으로 원문을 다시 타이핑하거나 요약본을 원문처럼 사용하지 않는다.

## 2. 허용되는 편집

- 페이지 분할
- 줄바꿈
- 문단 간 시각적 간격
- 표의 시각적 행·열 구성
- 페이지 번호와 브랜드 크레딧 추가
- 원문과 분리된 이미지 캡션·출처 추가

## 3. 금지되는 편집

- 문장 또는 단어 삭제
- 맞춤법·띄어쓰기 교정
- 인명·날짜·수치 교정
- 괄호·각주·URL 제거 또는 축약
- 문장 순서 변경
- 요약·재작성·의역
- 앞 페이지 내용을 뒤 페이지에서 다시 반복
- 페이지 사이 원문 구간을 건너뜀

## 4. 페이지 오프셋 규칙

`page-map.json`의 각 원문 페이지는 다음 값을 가진다.

```json
{
  "page": 10,
  "source_start": 5312,
  "source_end": 6078
}
```

강제 조건:

- 첫 원문 페이지의 `source_start`는 0이다.
- 마지막 원문 페이지의 `source_end`는 source.txt의 길이와 같다.
- 페이지 N의 `source_end`와 페이지 N+1의 `source_start`는 같다.
- 오프셋이 겹치면 중복, 벌어지면 누락으로 실패한다.
- 1~10장과 11~20장을 나눠 작업해도 동일한 page-map.json을 쓴다.

## 5. 표 보존

- 열 이름, 행 이름, 셀 값, 순위를 그대로 유지한다.
- 셀 안의 줄바꿈만 허용한다.
- 표가 넓으면 두 페이지로 분할하지만 행 순서를 바꾸지 않는다.
- 사진 때문에 표 행을 삭제하거나 축약하지 않는다.

## 6. 누락·중복 검수

1. 페이지 순서대로 본문·표 텍스트를 `text-manifest.txt`에 기록한다.
2. 디자인용 줄바꿈과 푸터만 제거한다.
3. 원문 정규화 문자열과 매니페스트 정규화 문자열을 비교한다.
4. 다음 결과를 `QA_REPORT.md`에 기록한다.

```text
source_chars: N
manifest_chars: N
missing_chars: 0
duplicated_chars: 0
order_mismatch: 0
offset_gaps: 0
offset_overlaps: 0
```

하나라도 0이 아니면 완료 처리하지 않는다.

## 7. 고정 장수와 충돌할 때

사용자가 20장을 정확히 요구한 경우:

1. 사진 면적을 줄인다.
2. 승인된 2열 본문을 사용한다.
3. 표를 허용 범위 안에서 조밀하게 배치한다.
4. 사진 없는 body 페이지를 늘리고 다른 페이지의 사진 면적을 조정한다.

하지 않는 것:

- 원문 삭제
- 본문 폰트 임의 축소
- 자간 과도 축소
- 문장 순서 변경

고정 폰트와 20장 안에 물리적으로 수용할 수 없을 때만 렌더링 전에 충돌을 알린다.

## 8. 의심되는 원문 오류

사실 오류, 오탈자, 중복, 잘못된 날짜가 의심돼도 원문 보존 모드에서는 고치지 않는다. 별도의 `QA NOTE`에서만 지적한다.
