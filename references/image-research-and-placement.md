# Image Research & Placement — 텍스트 중심 이미지 조사와 배정

## 1. 역할

사진은 본문을 이해시키는 보조 자료다. 사진을 확보했다는 이유로 본문을 요약하거나 그래프로 바꾸지 않는다. 적합한 사진이 없으면 텍스트만으로 완성할 수 있다.

## 2. 조사 전에 필요한 것

각 페이지에 다음을 정의한다.

- 원문 범위와 설명할 핵심 대상.
- 필요한 시각 역할: 실제 인물 / 특정 경기 / 제도·현장 / 장비 / 근거 캡처 / 필요 없음.
- 특정 날짜·대회 사진이어야 하는지, 과거 참고 사진도 가능한지.
- 고정 폰트로 본문을 전부 배치한 뒤 남는 폭·높이.
- 사용자가 요청한 출처 범위: 제공 사진만 / 링크 지정 / 외부 검색 허용 / 생성 금지.

텍스트 중심 기본값에서는 cover도 사진 필수가 아니다. 표 페이지는 사진 금지다.

## 3. 자료 조사 순서

1. 사용자 업로드 및 ZIP의 실제 파일을 점검한다. 기존 다운로드 사본과 중복 제거한다.
2. 지정 링크가 있으면 해당 파일 페이지와 사용 조건을 확인한다.
3. 외부 검색이 허용되면 대회·연맹·선수/팀의 공식 자료, Wikimedia Commons 등 출처를 확인할 수 있는 자료를 검색한다.
4. 검색어는 원문 속 이름·대회명·연도·장면을 조합한다. 한국어 검색 후 해당 국가 언어·영어를 필요한 범위에서 사용한다.
5. 해당 페이지에 필요한 후보 2~3개를 우선 확보한다. 무관한 사진을 대량 수집하지 않는다.
6. 실제 파일을 다운로드해 디코딩·해상도·구도를 확인한다. 링크 확인과 파일 확보를 구분한다.

공식 사이트 사진이라고 자유 이용 가능한 것은 아니다. 작가·라이선스·이용 허락·게시 범위를 확인한다. 불명확하면 보류하거나 권리 검토 상태를 사용자에게 알리고 다른 자료를 선택한다.

## 4. 선택 기준과 제외

질문: **이 사진이 없으면 독자의 이해가 실제로 약해지는가?**

우선: 원문 적합성 → 사실 맥락 → 권리 → 해상도 → 무크롭 배치 적합성 → 시각적 다양성.

제외 후보:

- 같은 사진의 재압축·다른 파일명·같은 구도의 연사 중복.
- 원문과 무관한 군중·안내판·보도진·기념사진.
- 사진 때문에 본문이 작아지거나 잘리는 구성.
- 특정 경기의 사진인 것처럼 오인하게 만드는 다른 연도 자료.
- 출처나 권리가 불분명한 검색 썸네일.

인물 이름·대회·연도는 출처 설명과 명시적 메타데이터로 확인한다. 얼굴만 보고 신원을 추정하지 않는다.

## 5. 자산 기록

`asset-map.json`과 `IMAGE_SOURCES.md`에 다음을 남긴다.

- id, local_path, origin, source_url, original_url.
- 작가, 라이선스·권리 상태, 확보 날짜.
- 실제 촬영 시점·대회, 원문 사건과의 관계.
- 해상도, SHA-256, 유사 이미지 검토 결과.
- used_on, 선택 이유, 제외 이유, 변환 내역.
- 캡처라면 PDF 페이지 / 영상 시간코드 / 앱·웹 화면 제목.

파일을 못 받았으면 downloaded-original로 기록하지 않는다. 사진에 필요한 크레딧은 production 문서뿐 아니라 라이선스가 요구하는 게시 위치에도 남긴다.

## 6. 배치 알고리즘

1. 제목·본문·원문 표·각주를 고정 크기로 먼저 배치한다.
2. 실제 남는 직사각형을 계산한다.
3. 사진이 설명에 도움이 되고 충분히 보일 때만 그 영역에 contain으로 배치한다.
4. 텍스트 패널로 전경을 가리지 않는다. 원본 전체가 보이는 배율을 사용한다.
5. 남는 가장자리만 같은 사진의 블러·톤다운 배경으로 채울 수 있다.
6. 사진을 넣으려 본문 범위를 줄이지 않는다. 부족하면 사진을 줄이거나 없앤다.

기본 사진 슬롯은 본문 아래 가로 띠, 문단 옆 작은 보조 컷, 관련 두 사진의 짧은 비교 슬롯이다. 사진 위 긴 본문은 피하고 글은 깨끗한 단색 패널에 둔다. caption은 장면 설명·출처만 넣고 다운로드·원문 파일 안내는 넣지 않는다.

## 7. 대체 시각물

사진이 필요한 페이지에만 검토한다. 텍스트만으로 충분한 장을 억지로 채우지 않는다.

- 실제 근거 화면이 적합하면 실제 웹/PDF/영상 캡처를 사용한다. 가능한 도구로 실제 캡처했을 때만 캡처라고 기록한다.
- 수치가 있으면 코드 그래프·표, 구조가 있으면 코드 도식을 보조로 만들 수 있다.
- 원래 문장과 원래 표는 그대로 둔다. 보조 시각화에 수치가 반복돼도 본문 보존 검사를 생략하지 않는다.
- 실제 수치 없는 그래프, 원문에 없는 인과관계, 가짜 화면 캡처를 만들지 않는다.
- 작은 친근한 2D 아이콘·캐릭터는 사용자가 허용했을 때 마지막 수단으로만 사용한다. 사실 증거처럼 쓰지 않는다.
- `생성 기능 금지`는 생성형 AI 자산 금지다. Python/SVG로 만드는 정확한 표·그래프까지 금지하는 뜻은 아니다.

## 8. 다운로드 실패와 일괄 전달

접근 제한을 우회하지 않는다. 정상적인 재시도는 서버 Retry-After와 요청 간격을 존중한다. 실패하면 성공 파일만 명확히 구분하고 직접 받을 수 있는 출처 링크를 제공한다. 불완전한 묶음을 전부 받은 것처럼 안내하지 않는다.

사용자가 ZIP을 요청하면 실제 확보 파일과 크레딧·성공/실패 목록을 묶고 ZIP이 열리는지 확인한다. 사용자가 가져온 사본을 다시 받은 경우 해시·시각적 유사성으로 중복을 제거한다.

## 9. 공개와 내부 분리

검색어, 후보 순위, 다운로드 실패, 선택·제외 사유, 라이선스 검토 과정은 production/internal 문서에 둔다. 독자에게 필요한 장면 설명·촬영 시점·사진 크레딧만 public 캡션으로 내보낸다.
