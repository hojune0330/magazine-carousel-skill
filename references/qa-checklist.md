# QA Checklist — Report Carousel v3.1

완료 전 아래 항목을 모두 확인한다.

## 1. Production mode

- [ ] 다장 캐러셀을 image_gen이 아닌 결정론적 파일 렌더링으로 만들었는가
- [ ] 요청한 전체 장수를 한 실행에서 렌더링했는가
- [ ] 실제 PNG·ZIP·preview·검수 파일이 존재하는가

## 2. Canvas & fixed brand system

- [ ] 캔버스가 1080×1350 (4:5)인가
- [ ] 좌우 여백이 일관적인가
- [ ] 노란 세로 바 위치가 동일한가
- [ ] 영문 라벨 위치와 크기가 동일한가
- [ ] 제목 역할별 크기·굵기·줄간격이 동일한가
- [ ] 푸터 구분선, 페이지 번호, 크레딧 위치가 동일한가

## 3. Large typography

- [ ] 데크 전체가 `reading-large` 또는 `source-dense-large` 한 프리셋을 쓰는가
- [ ] 일반 본문이 20px 이상인가
- [ ] 기본 편집형 본문은 23/35에 가까운가
- [ ] 장문 원문형 본문은 21/32에 가까운가
- [ ] 오버플로를 맞추기 위해 특정 장만 폰트를 줄이지 않았는가
- [ ] 제목을 맞추기 위해 장별 크기를 바꾸지 않았는가
- [ ] 모바일 25% 축소에서도 본문이 읽히는가

## 4. Text-first adaptive layout

- [ ] 제목·본문 bounding box를 먼저 측정했는가
- [ ] 패널 높이가 실제 텍스트 높이 + 패딩으로 계산됐는가
- [ ] 사진 영역이 패널 계산 후 남은 공간을 사용했는가
- [ ] 글자가 적은 페이지는 패널이 줄고 사진이 커졌는가
- [ ] 글자가 많은 페이지는 사진이 줄거나 body-balanced로 전환됐는가

## 5. Fill & whitespace

목표:

```yaml
normal_vertical_fill: 0.86~0.97
panel_utilization: 0.72~0.92
table_vertical_fill: 0.72~0.92
```

- [ ] 140px 이상 연속된 의도하지 않은 빈 띠가 없는가
- [ ] usable height의 10% 이상인 무의미한 빈 영역이 없는가
- [ ] 일반 보고서 페이지에서 본문 끝과 푸터 사이 180px 이상 공백이 없는가
- [ ] panel utilization이 0.65 미만 또는 0.96 초과인 장이 없는가
- [ ] 본문이 짧은데 고정 패널이 화면 절반 이상을 차지하지 않는가
- [ ] 표지·챕터 오프닝의 여백만 의도적 예외로 표시됐는가

## 6. Page balancing

- [ ] Pass 1 용량 분할을 수행했는가
- [ ] Pass 2 인접 페이지 underfill/overfill 재균형을 수행했는가
- [ ] underfill 페이지에 다음 페이지의 완전한 문장·문단을 당겼는가
- [ ] overfill 페이지의 마지막 완전한 문장·문단을 다음 장으로 넘겼는가
- [ ] 문장·문단 순서가 유지됐는가
- [ ] 제목 뒤 최소 2줄 본문이 남았는가
- [ ] 문단 첫 줄/마지막 한 줄 고립이 없는가
- [ ] 표 행을 중간에서 나누지 않았는가

## 7. Photos

- [ ] 사진 장에서도 헤더·제목·푸터 체계가 유지되는가
- [ ] 전경 사진이 contain·무크롭인가
- [ ] 얼굴, 머리, 손, 발, 결승선, 허들, 배턴이 잘리지 않았는가
- [ ] 남는 영역은 동일 사진 blur/tone-down 배경으로 처리됐는가
- [ ] 긴 본문을 사진 위에 직접 올리지 않았는가
- [ ] 사진 밝기·색온도가 데크 안에서 크게 튀지 않는가
- [ ] 같은 사진이 승인 없이 반복되지 않았는가
- [ ] 사진이 텍스트와 실제 내용상 연결되는가

## 8. Tables & data

- [ ] 표 페이지에 사진이 전혀 없는가
- [ ] 웜화이트 배경 + 얇은 검정·회색 선인가
- [ ] 표 폰트가 선택한 프리셋으로 전 장 동일한가
- [ ] 행 높이가 64~118px 범위에서 균형 있게 배분됐는가
- [ ] 표가 상단에 몰리고 하단이 크게 비지 않는가
- [ ] 표를 맞추기 위해 글자를 줄이지 않았는가
- [ ] 날짜, 기록, 순위, 비고가 원문과 일치하는가

## 9. Source-highlight

- [ ] 원문에 실제 존재하는 문장·수치만 강조했는가
- [ ] 새로운 주장이나 수치를 만들지 않았는가
- [ ] 같은 구절을 본문과 highlight에 중복 표시하지 않았는가
- [ ] text-manifest에는 원문 순서대로 한 번만 기록했는가

## 10. Source-preserving mode

- [ ] 원문의 모든 글자·숫자·괄호·각주·URL이 유지됐는가
- [ ] 문장 순서가 유지됐는가
- [ ] 표 열·행·셀 값이 유지됐는가
- [ ] 10→11장 등 페이지 경계가 정확히 이어지는가
- [ ] `text-manifest.txt` 비교 결과 누락 0인가

필수 수치:

```text
missing_chars: 0
duplicated_chars: 0
order_mismatch: 0
offset_gaps: 0
offset_overlaps: 0
```

## 11. Image source honesty

- [ ] user-upload와 downloaded-original을 구분했는가
- [ ] 검색 링크만 본 이미지를 실제 사용했다고 주장하지 않았는가
- [ ] 온라인 원본 URL, 작가, 라이선스, 다운로드 날짜를 기록했는가

## 12. Final visual check

- [ ] 개별 PNG를 100% 확대해 확인했는가
- [ ] 모바일 25% 축소를 확인했는가
- [ ] 전체 콘택트시트에서 서로 다른 템플릿처럼 보이지 않는가
- [ ] 한 장만 유독 글자가 작거나 큰 페이지가 없는가
- [ ] 페이지 번호가 연속적인가
- [ ] 크레딧이 모든 장에 존재하는가

하나라도 실패하면 완료 처리하지 않고 페이지 맵을 수정해 재렌더링한다.
