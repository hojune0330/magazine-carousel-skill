# Request Routing — 사용자의 말을 제작 모드로 해석하는 법

이 문서는 사용자가 짧게 말해도 제작 방식, 자산 입력, 이미지 부족 대응을 틀리지 않도록 하는 최우선 분기표다.

## 1. 파일 렌더링 모드로 즉시 해석

아래 표현이 포함되면 질문 없이 파일 렌더링 모드로 들어간다.

- 스킬대로
- 파일로
- 렌더링해서
- 캐러셀 전체
- 20장 전체
- PNG와 ZIP
- 이미지 생성 기능 쓰지 말고
- 앞 10장에 이어서
- 1~20장 한 번에
- 원문 빠짐없이

실행 규칙:

- 최종 레이아웃과 한국어 본문에 image_gen 사용 금지
- 10장 생성 제한 적용 금지
- Python/Pillow, SVG, HTML/CSS 등으로 전체 장수 렌더링
- 실제 PNG·ZIP·미리보기·검수 파일 생성

## 2. `이미지 만들어`의 맥락 해석

`이미지 만들어`라는 표현만 보고 image_gen으로 가지 않는다.

다음 맥락이면 파일 렌더링이다.

- 카드뉴스, 캐러셀, 슬라이드, 페이지 수가 언급됨
- 원문, 표, 페이지 번호, 크레딧, ZIP이 있음
- 기존 템플릿이나 스킬 적용 요청
- 앞 장과 뒤 장의 연속성이 중요함

다음 경우에만 전체 생성형 이미지 모드다.

- 한 장 포스터를 새로 그림
- 일러스트, 장면, 합성, 스타일 변환을 명시
- 생성형 이미지로 만들라고 명시

보조 아이콘·캐릭터·일러스트 생성은 전체 페이지 생성과 다르다. 별도 자산으로만 만들고 최종 페이지는 파일 렌더링한다.

## 3. 20장 요청

`20장 만들어`는 20개의 생성 이미지를 요청한 것이 아니라 20페이지 파일 산출물을 요청한 것으로 해석한다.

- 01.png~20.png를 한 번에 렌더링
- `최대 10장` 안내 금지
- 전체 원문·페이지·자산 맵을 하나로 관리

## 4. 이어 만들기 요청

`다음 10장`, `11~20장`, `앞의 작업에 이어서`는 새 문서를 시작하라는 뜻이 아니다.

- 기존 source.txt와 page-map.json을 다시 읽는다.
- 직전 페이지 마지막 문자 다음부터 이어간다.
- 이전 페이지 내용을 반복하지 않는다.
- 최종 전체 콘택트시트를 다시 만들어 순서를 확인한다.

## 5. 큰 본문·빈 공간 개선 요청

다음 표현은 `large-type adaptive-fill`로 즉시 해석한다.

- 본문이 작아
- 원문 글자를 더 크게
- 텍스트가 조금 작아
- 빈 공간이 눈에 띄어
- 공백을 줄여
- 사진이나 레이어를 텍스트에 맞춰
- 텍스트 먼저 크게 잡아
- 사진을 더 크게 채워
- 지금보다 꽉 차게

자동 적용:

1. `reading-large`를 기본 적용한다.
2. 원문 전체 + 고정 장수 장문이면 `source-dense-large`를 데크 전체에 적용한다.
3. 일반 본문을 20px 미만으로 내리지 않는다.
4. 제목·본문 bounding box를 먼저 측정한다.
5. 패널 높이를 텍스트 높이 + 패딩으로 계산한다.
6. 남은 영역을 사진·그래프·도식에 배분한다.
7. underfill/overfill 페이지를 인접 페이지와 재균형한다.
8. 큰 의도하지 않은 빈 띠가 남으면 재렌더링한다.

하지 않는 것:

- 장별 본문 폰트 축소
- 고정 패널에 작은 글자를 우겨넣기
- 의미 없는 아이콘·박스·근거 없는 그래프로 공간 채우기

## 6. 이미지 업로드 해석

### 사용자가 사진을 올림

- 실제 업로드 파일을 사용한다.
- 생성형 이미지로 다시 만들지 않는다.
- JPG/JPEG, PNG, WebP를 우선한다.
- HEIC/HEIF, TIFF, BMP는 변환 후 사용한다.
- 파일 해시와 시각적 유사성으로 중복을 확인한다.
- 기본적으로 한 사진은 한 번만 사용한다.
- 전경 사진은 무크롭 contain을 적용한다.

### 사용자가 ZIP을 올림

- 내부 폴더와 파일명을 유지해 자산 목록을 만든다.
- photos, screenshots, logos, documents, data 폴더를 구분한다.
- asset-notes.csv가 있으면 페이지 선호와 출처 메모를 반영한다.

### 사용자가 PDF·문서·데이터를 올림

- PDF는 필요한 페이지의 표·차트·그림을 캡처 또는 추출한다.
- CSV/XLSX/JSON은 그래프·표 생성 원본으로 사용한다.
- PPTX/DOCX는 참고 레이아웃과 내부 자산 추출용으로 사용한다.

### 사용자가 동영상을 올림

- 프레임 캡처 허용 맥락이 있을 때만 사용한다.
- 시간코드를 기록한다.
- 모션블러가 심한 프레임은 제외한다.

## 7. 온라인 이미지 검색 요청

- 실제 원본 파일을 다운로드해야 한다.
- 검색 결과 링크나 썸네일만 보고 사용했다고 주장하지 않는다.
- 공식 기관·선수/팀 공식 채널·Wikimedia Commons 등 권리 확인 가능한 원본을 우선한다.
- 다운로드가 막히면 그 사실을 말한다.
- URL, 작가, 라이선스, 다운로드 날짜를 기록한다.

## 8. 이미지 부족 자동 보완 요청

다음 표현은 **자산 부족 자동 보완 모드**다.

- 이미지가 부족하면 알아서 채워
- 사진 부족하면 다른 방식으로
- 그래프나 표를 만들어
- 실제 화면을 캡처해
- PDF에서 따와
- 경기 영상 프레임을 써
- 아이콘이나 캐릭터로 표현해
- 빈 페이지가 없게 구성해
- 사진 중복 없이 만들어

이때 별도 질문 없이 다음 순서로 판단한다.

```text
실제 업로드 이미지
→ 실제 원본 추가 다운로드
→ 실제 웹/PDF/영상/앱 캡처
→ 실제 데이터 그래프·표
→ 원문 기반 도식·타임라인
→ 저불쾌감 보조 아이콘·캐릭터·일러스트
→ 타이포그래피 중심 해결
```

페이지 성격에 따라 순서를 조정할 수 있다.

- 숫자·순위·기록: 그래프/표 우선
- 공식 발표·결과·화면: 실제 캡처 우선
- 시간 순서·훈련 구조: 타임라인/도식 우선
- 실제 인물·경기: 실제 사진 우선
- 초보 설명·가벼운 개념: 친근한 2D 아이콘/캐릭터 가능

선택 근거를 `VISUAL_FALLBACK_LOG.md`에 기록한다.

## 9. 생성형 보조 자산 허용과 금지

### 허용 문맥

- 작은 선형 아이콘
- 스포츠 실루엣
- 친근한 2D 캐릭터
- 건강·회복·훈련 개념 일러스트
- 추상 배경 패턴

### 자동 시각 프로필

- clean flat 2D
- healthy, calm, friendly
- uncanny level very low
- discomfort level very low
- 폭력, 피, 주사, 수술, 체액, 공포, 신체 왜곡, 성적 대상화 없음

### 사용 금지 문맥

사용자가 다음처럼 말하면 generated-* 자산도 사용하지 않는다.

- 이미지 생성 기능 쓰지 말고
- 생성형 이미지 금지
- 실제 자료만 사용
- 내가 준 사진만 사용

이때는 실제 사진·실제 캡처·그래프·표·도식·타이포그래피만 사용한다.

## 10. 표 요청

표, 랭킹, 기록표, 일정표가 있는 페이지는 사진 없는 `table-balanced` 타입이다.

- 사진 배경 금지
- 얼굴과 경기 장면을 표 뒤에 깔지 않음
- 웜화이트 배경 + 얇은 선 + 고정 표 폰트
- 남는 높이는 행 높이와 표 위치로 균형 조정
- 표를 맞추기 위한 폰트 축소 금지

## 11. 그래프 요청

- 실제 원문·CSV·XLSX·공식 결과 데이터만 사용한다.
- 축, 단위, 기간, 기준, 출처를 표시한다.
- 3D 그래프와 장식성 원형 차트 남발을 피한다.
- 숫자 근거가 없는 내용을 가짜 수치 그래프로 만들지 않는다.
- 그래프 글자와 레이블은 결정론적 코드 렌더링으로 만든다.

## 12. 실제 캡처 요청

- 공식 웹페이지, PDF, 공식 영상, 앱 화면에서 실제로 캡처한다.
- URL, 페이지 제목, 캡처 날짜, PDF 페이지, 영상 시간코드를 기록한다.
- 데이터나 문구를 변조하지 않는다.
- 개인정보는 가린다.
- 유료 장벽을 우회하거나 기사 전체를 복제하지 않는다.

## 13. 원문 보존 표현

다음 표현은 모두 원문 보존 모드다.

- 원문 그대로
- 한 글자도 빼지 마
- 단어와 문장 모두 유지
- 표도 그대로
- 내용 빠짐없이

허용되는 편집은 페이지 분할, 줄바꿈, 원문 구절의 시각적 highlight 승격뿐이다. highlight는 본문과 중복하지 않는다.

## 14. 사용자에게 되묻지 않아도 되는 것

기본값:

- 인스타그램 4:5 = 1080×1350
- 브랜드 라벨 = ELITE REPORT
- 크레딧 = @io_magazine / 장호준 코치
- 읽기 프리셋 = reading-large
- 원문 장문 + 고정 장수 = source-dense-large
- 표 페이지 = 사진 없음
- 사진 전경 = 무크롭 contain
- 빈 공간 = 패널 축소 + 사진/그래프/도식 확대 + 인접 문단 재균형
- 사진 주변 = 같은 사진 blur·tone-down 배경
- 보조 생성 이미지 = 마지막 수단, 매우 낮은 불쾌감
- 산출물 = PNG, ZIP, preview, text manifest, page map, asset map, asset audit, visual fallback log, image sources, QA report

사용자가 다른 값을 명시할 때만 바꾼다.
