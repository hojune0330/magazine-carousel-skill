# Request Routing — 사용자의 말을 제작 모드로 해석하는 법

이 문서는 사용자가 짧게 말해도 작업 방식을 틀리지 않도록 하는 최우선 분기표다.

## 1. 파일 렌더링 모드로 즉시 해석

아래 표현이 포함되면 질문 없이 파일 렌더링 모드로 들어간다.

- 스킬대로
- 파일로
- 렌더링해서
- 캐러셀 전체
- 20장 전체
- PNG와 ZIP
- 이미지 생성 기능 쓰지 말고
- 앞 10장에 이어서
- 1~20장 한 번에
- 원문 빠짐없이

실행 규칙:

- image_gen 사용 금지
- 10장 생성 제한 적용 금지
- Python/Pillow, SVG, HTML/CSS 등으로 전체 장수 렌더링
- 실제 PNG·ZIP·미리보기·검수 파일 생성

## 2. `이미지 만들어`의 맥락 해석

`이미지 만들어`라는 표현만 보고 image_gen으로 가지 않는다.

다음 맥락이면 파일 렌더링이다.

- 카드뉴스, 캐러셀, 슬라이드, 페이지 수가 언급됨
- 원문, 표, 페이지 번호, 크레딧, ZIP이 있음
- 기존 템플릿이나 스킬 적용 요청
- 앞 장과 뒤 장의 연속성이 중요함

다음 경우에만 생성형 이미지 모드다.

- 한 장 포스터를 새로 그림
- 일러스트, 장면, 합성, 스타일 변환을 명시
- 생성형 이미지로 만들라고 명시

## 3. 20장 요청

`20장 만들어`는 20개의 생성 이미지를 요청한 것이 아니라 20페이지 파일 산출물을 요청한 것으로 해석한다.

- 01.png~20.png를 한 번에 렌더링
- `최대 10장`이라는 안내 금지
- 20장 전체의 원문·페이지·이미지 맵을 하나로 관리

## 4. 이어 만들기 요청

`다음 10장`, `11~20장`, `앞의 작업에 이어서`는 새 문서를 시작하라는 뜻이 아니다.

- 기존 source.txt와 page-map.json을 다시 읽는다.
- 직전 페이지 마지막 문자 다음부터 이어간다.
- 이전 페이지의 내용을 반복하지 않는다.
- 최종 1~20장 콘택트시트를 다시 만들어 전체 순서를 확인한다.

## 5. 이미지 입력 해석

### 사용자가 사진을 올림

- 실제 업로드 파일을 사용한다.
- 생성형 이미지로 다시 만들지 않는다.
- 파일 해시와 시각적 유사성으로 중복을 확인한다.
- 기본적으로 한 사진은 한 번만 사용한다.

### 사용자가 온라인 검색을 요청함

- 실제 원본 파일을 다운로드해야 한다.
- 검색 결과 링크만 보고 사용했다고 주장하지 않는다.
- 다운로드가 막히면 그 사실을 말하고 사용자 제공 사진으로 대체할지 확인한다.
- 작가·라이선스·원문 URL을 기록한다.

## 6. 표 요청

표, 랭킹, 기록표, 일정표가 있는 페이지는 무조건 사진 없는 `table` 타입이다.

- 사진 배경 금지
- 얼굴과 경기 장면을 표 뒤에 깔지 않음
- 웜화이트 배경 + 얇은 선 + 고정 표 폰트

## 7. 원문 보존 표현

다음 표현은 모두 원문 보존 모드다.

- 원문 그대로
- 한 글자도 빼지 마
- 단어와 문장 모두 유지
- 표도 그대로
- 내용 빠짐없이

이 경우 허용되는 편집은 페이지 분할과 줄바꿈뿐이다.

## 8. 사용자에게 되묻지 않아도 되는 것

다음은 스킬 기본값으로 자동 결정한다.

- 인스타그램 4:5 = 1080×1350
- 기본 브랜드 라벨 = ELITE REPORT
- 기본 크레딧 = @io_magazine / 장호준 코치
- 표 페이지 = 사진 없음
- 사진 전경 = 무크롭 contain
- 빈 공간 = 같은 사진의 블러·톤다운 배경
- 산출물 = PNG 전체, ZIP, preview, text manifest, page map, image sources, QA report

사용자가 다른 값을 명시할 때만 바꾼다.
