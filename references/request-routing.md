# Request Routing v3.3 — 짧은 지시의 실제 의미

## 파일 렌더링

`스킬대로 / 파일로 / 렌더링 / 전체 20장 / PNG·ZIP / 이어서 / 원문 빠짐없이`는 전체 파일 제작이다. 생성형 포스터 도구로 전환하거나 10장으로 끊지 않는다.

## 원문 중심

`글 전부 / 단어 그대로 / 문장구성 그대로 / 요약하지 마 / 표·그래프는 부가적 / 사진은 쓰되 글자 위주`는 선택 원문을 모두 공개 슬라이드에 담으라는 뜻이다. 요약 슬라이드+원문 첨부파일로 대체하지 않는다.

`지금 만든 수준이 딱 좋다`는 승인한 실제 출력과 스타일을 계승하라는 뜻이다. 예전 사진 중심 템플릿이나 더 작은 본문 프리셋으로 돌아가지 않는다. 신규 기본은 본문 26/39이며 장별 축소하지 않는다.

## 불필요한 문구 제거

`위에 풀 텍스트 / 아래 원문은 파일에 수록 / 관객에게 보이면 안 돼`는 **슬라이드 이미지 속 제작 메타정보를 제거**하라는 지시다. 결과 안내문을 줄이라는 뜻이 아니다.

- public: 콘텐츠 제목·본문·표·필수 출처·사진 크레딧.
- production: 원문 보존 설명, 첨부파일 안내, QA, 제작 방식. 보고서·전달 메시지 허용.
- internal: 해시·매니페스트·디버그 로그.

`보고서에는 있어도 돼`를 무시하고 작업 기록을 지우지 않는다.

## 사진과 자료 조사

`이미지도 잘 붙여 / 이미지 자료 조사 / 사진 부족하면 알아서`는 본문을 확보한 뒤 관련 자료를 조사·선별하라는 뜻이다. 모든 페이지에 사진을 강제하지 않는다.

업로드 → 필요도 정의 → 실제 원본/근거 조사 → 권리·해상도·중복 확인 → 남은 공간 배정 → 캡션·출처 → 검사 순으로 진행한다. 상세는 image-research-and-placement.md를 따른다.

## 표·그래프

원래 표는 원문으로 보존한다. 추가 그래프는 보조이며 문장을 없애지 못한다. 표 페이지에는 사진이 없다. 데이터 출처가 불명확하면 가짜 그래프를 만들지 않는다.

## 생성 금지

`이미지 생성 기능 쓰지 말고`는 생성형 AI 보조 에셋까지 금지한다. Python/SVG로 정확한 표·그래프·도형을 렌더링하는 것은 생성형 이미지 사용이 아니다. `내가 준 사진만`은 외부 이미지 확보도 금지한다.

## 특정 장 수정

`2·3장만 다시`는 해당 장의 내용·원문 범위와 번호를 유지하며 레이아웃을 수정한다. 나머지 장은 바꾸지 않는다. 원문 재분할이 다른 장에 영향을 주면 전체 연결부를 점검한다.

## GitHub 업데이트

실제 문서를 읽고 변경한 뒤 커밋·readback 확인을 수행한다. 정리문만 보여주고 저장했다고 하지 않는다. 스킬 업데이트와 기존 PNG 재렌더링, 새 채팅 자동 로드는 서로 다른 작업이다.
